## Arbitrage safety

The arbitrage scanner uses executable order-book asks and top-level depth, then
refreshes both legs immediately before an order. Paper mode is the default. Set
`ADMIN_PASSWORD` to protect trading, settlement, risk, venue, and agent mutations.

Live execution is fail-closed: Kalshi orders use its V2 fill-or-kill endpoint,
while Polymarket and SX.bet remain view-only until equivalent authenticated FOK
adapters are implemented and tested. JSON files are written atomically and locked
for a single shared filesystem; use a transactional database before running more
than one application host.

Run the verification suite before changing execution logic:

```bash
npm test
npm run lint
npx tsc --noEmit
npm run build
```
